# M0-window-core handoff

window.rs 1-2561 and 7891-8411 are in window.go. Window fields keep upstream order; unexported names are the camelCase of upstream's, except `element_opacity` -> `currentElementOpacity` (clashes with the `elementOpacity()` stub).

- api-contracts.md §1 lists `(Window).Focus`, `Spawn`, `SpawnWithPriority`, `Prompt`, `WindowHandle` as M0-window-core: their upstream lines are in 2562-7890, so they stay stubs (annotated M0-window-paint; `Prompt` M0-window-dispatch). `DispatchEventResult` (line 2532) moved here from the M0-window-dispatch row. An exit stage should fix the table.
- Contract changes: `ElementIDSource` is now `~string | ~int | ~int32 | ~uint | ~uint32 | ~uint64 | ElementID | *FocusHandle | *SourceLocation | [16]byte | [20]byte`; `NewElementID`'s signature is unchanged. New variant constructors: `ElementIDInteger`, `ElementIDUUID`, `ElementIDFocusHandle`, `ElementIDNamedUsize`, `ElementIDPath`, `ElementIDCodeLocation`, `ElementIDNamedChild`, `ElementIDOpaqueID`. `AnyWindowHandle` gained `rootEntityTypeName`. `FocusHandle` builders are `WithTabIndex` / `WithTabStop`, `PaintQuad` builders `WithCornerRadii` / `WithBorderWidths` / `WithBorderColor` / `WithBackground` (D-FIELDMETHOD, the fields keep upstream's names). `Hitbox` embeds `Bounds[Pixels]` (Deref), fields `ID`, `ContentMask`, `Behavior`. `WindowHandle[V].Update` takes `func(*V, *Window, *Context[V])` (shadows the embedded AnyWindowHandle.Update, as upstream); `UpdateR`, `ReadWith`, `AnyWindowHandle.UpdateR` / `Read` / `Downcast` are generic methods. `Root` and `Entity` return a clone the caller releases.
- M0-window-paint: replace the new stubs `Focused` (returns a handle the caller releases), `RemoveWindow`, `BoundsChanged`, `windowDisplayChanged(handle, cx)`, `buttonLayoutChanged`, `refreshVisibility`, `advanceSceneAnimations`, `present`, `IsWindowActive`, `MousePosition`, `LastInputWasKeyboard`. `Draw` must do `scope := enterElementArenaScope(cx.elementArena()); defer scope.End()` at the start and `return scope.exit(cx.elementArena())` at the end (upstream's ElementArenaScope enter/exit/Drop); `drawInProgress()` is upstream's `draw_in_progress`. Frame element states are `elementStateMap` (`get`, `insert`, `removeEntry`, `len`, `clear`, keyed by `elementStateKey{id GlobalElementID, typ reflect.Type}`). `pendingInputTimeoutDuration` is upstream's `PENDING_INPUT_TIMEOUT` (the type took the name). `pendingInputTimeout.release()` cancels / unsubscribes whatever state it holds: call it where upstream drops a `PendingInput`.
- M0-window-dispatch: replace `dispatchActionOnNode`, `handleA11yAction`. `frame.nextInspectorInstanceIDs` is `map[uint64][]inspectorInstanceIDs{path, next}` keyed by `InspectorElementPath` hash; change the entry shape freely.
- M0-window-a11y: replace `rootNodeID`, `nativeViewState`, `hitTestNativeView`, `dispatchKeyDownBeforeNativeView`, `focusNativeView`.
- M3-profiler-journal: no-op stubs `recordWindowVisibility`, `recordPlatformSignal`, `recordReentrantFrameSkipped`, `recordFrameSkipped`, types `PlatformSignal`, `FrameSkipReason`. M3-profiler-hang: `DebugFrameOverlay` / `NewDebugFrameOverlay` (placeholder returns the zero value; only called when `profilerFeatureEnabled`).
- M0-window-tests: `test_focus_handle_release` is the Drop-table test for `FocusHandle.Release` (D-RAII); none of the window.rs tests are ported here.
- Owner of app_test_context.go (exit stage): `VisualTestContext.Draw` must wrap its body in `scope := enterElementArenaScope(app.elementArena()); defer scope.End()` and finish with `scope.exit(app.elementArena()).Clear(app)`, as upstream test_context.rs:1060-1074 does; otherwise view drops queued during the draw are never run.
