# Handoff: M0-scene

- M0-window-core: `HitboxID` is stubbed in stubs.go as `type HitboxID uint64`; keep that type (scene tests build `HitboxID(0)` and `HitboxID(0)+1` for `placeholder()` / `next()`). `ContentMask::scale` is not stubbed: `NewPaintedPath` inlines its body (`ContentMask[ScaledPixels]{Bounds: m.Bounds.Scale(f)}`); port the method on `ContentMask[T]` (rule N7) as usual.
- M0-elements-media: `TimedTransformation` and `Transformation` are stubbed with the unexported methods scene.go calls (`minFrameInterval() (time.Duration, bool)`, `at(time.Duration) Transformation`, `alphaFactor() float32`, `intoMatrix(Point[Pixels], float32) TransformationMatrix`). `Window` builds animated sprites with the unexported `newSpriteAnimation` and `Scene.insertAnimatedSprite`; `Scene.animationFrameInterval` / `advanceAnimations` are what window.rs calls.
- M0-window-paint / Apple stages: every `MonochromeSprite` / `SubpixelSprite` must set `Transformation` (unit matrix for none) and `Animation: SpriteAnimationIDNone`; Go zero values differ from upstream's defaults (docs/api-contracts.md section 7). `PaintSurface.ImageBuffer` is a `uintptr` CVPixelBufferRef: upstream's `CFRetained` retains it for the primitive's lifetime, so the macOS / iOS paint_surface and renderer must retain on insert and release when the scene is cleared or replaced.
- M0-exit (fix authority on geometry.go): `Point[T].GoString` prints large floats as `3.4028235e+38`; Rust's `{:?}` prints `3.4028235e38`. Visible in path_winding's overflow warning (`TestPathWinding_OverflowingPathsAreSkipped -v`).
- Lint (not M0-scene paths): `go run ./internal/cmd/paritycheck -lint` currently fails on internal/linux/wl/display.go:285 (LockOSThread outside package platform) and internal/linux/xcbshim/setup.go:5 (non-godoc comment).
