# Handoff: M0-platform-types

Shapes fixed in stubs.go on behalf of later stages (docs/api-contracts.md sections 1 and 6):

- M0-text-system: `FontMetrics` has upstream's public fields (`Ascent`, `Descent`, `LineGap`, `UnderlinePosition`, `UnderlineThickness`, `CapHeight`, `XHeight`, `BoundingBox`, `UnitsPerEm`). Upstream also has methods of the same names taking a font size (`FontMetrics::ascent(font_size)`, text_system.rs:1225-1260); Go cannot have a field and a method with one name, so those methods need other names and a dev id in core-text.md. `NoopTextSystem` (platform.go) reads the fields. `LineLayout`, `ShapedRun`, `ShapedGlyph` fields, `FontID uint`, `GlyphID uint32`, `RenderGlyphParams` (comparable, `SubpixelVariant PointOf[uint8]` since `Number` excludes uint8) and `MissingGlyphSink.Report([]MissingGlyph)` are set; `AtlasKey` is a map key, so `RenderGlyphParams` must stay comparable.
- M0-profiler-core: `const profilerFeatureEnabled = false` in stubs.go gates `PlatformFrameSignal` (platform.rs `cfg(feature = "profiler")`). Replace it with one definition per tag in profiler_on.go (`true`) / profiler_off.go (`false`); platform_test.go's frame-signal tests gate on the const at run time.
- M0-platform-data: the 2127+ types are stubbed (`WindowParams`, `WindowBounds`, `WindowAppearance` and `WindowBackgroundAppearance` / `TextRenderingMode` / `PromptLevel` with all variants, `PathPromptOptions`, `PromptButton`, `CursorStyle`, `ClipboardItem`, `PlatformInputHandler`, `TextInputConfiguration`, `Menu`, `MenuItem`, `OwnedMenu`). The interfaces take `*PlatformInputHandler` (nil for None) and `[]PromptButton`. The tests of platform.rs 3694-4113 (platform_test.go) are yours: the atlas tests use `NewAtlasState(&recordingBackend{})` with `Clear(func(b *recordingBackend))`; `WindowButtonLayoutParse`, `WindowButtonLayoutLinuxDefault` and the unexported `(WindowButtonLayout).format` are in platform.go and build on every GOOS, so the button-layout tests (cfg linux upstream) can run everywhere or skip on `runtime.GOOS`; platform_test.go needs no build constraint. The frame-signal tests (cfg profiler / not profiler) cannot be split into tagged files you own: gate them at run time on `profilerFeatureEnabled`.
- M0-input-types: `Capslock{On bool}`, `KeyDownEvent`, `KeybindingKeystroke` + `KeybindingKeystrokeFromKeystroke` (DummyKeyboardMapper calls it), `ExternalDragPayload` (sealed interface; `StartExternalDrag` takes it by value), `RenderImageParams{ImageID, FrameIndex int}`, `ImageID uint`.
