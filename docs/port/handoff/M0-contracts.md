# M0-contracts handoff

docs/api-contracts.md is the contract as built; these are the points other stages must act on.

- M0-div-api: `InteractiveElement::id` is `(InteractiveID[S]).ID` on its own mixin (D-IDMIXIN, registered in core-geometry.md). `Interactive[S].ID` returning `*Stateful[S]` while `Stateful[E]` embeds `Interactive[*Stateful[E]]` fails with "instantiation cycle". Set the core-elements.md row `InteractiveElement::id` to `(InteractiveID[S]).ID` / `dev:D-IDMIXIN`. Every element upstream gives `id` embeds and binds `InteractiveID`; `Stateful[E]` does not.
- Exit stage (paritycheck owner): add `InteractiveID` to `mixinTypes` in internal/cmd/paritycheck/matrix/lint.go so an element declaring its own `ID` is caught.
- M0-input-types: gpui.go declares the free functions `SetGlobal`, `UpdateGlobal`, `UpdateGlobalR`, `UpdateDefaultGlobal`, `UpdateDefaultGlobalR` (BorrowAppContext, D-CTX), so global.rs's `UpdateGlobal` trait cannot be a Go type of that name; its `update_global` / `set_global` are the same operations as these functions. `ReadGlobal` is not taken at package level. `ActionData.JSONSchema` is `func() *jsonschema.Schema` (actiongen's handoff) and `Build` takes `jsontext.Value`.
- M0-executors: gpui.go already declares the executor.rs re-exports `Task`, `FallibleTask`, `Priority`, `DedicatedExecutor`, `SchedulerLocalExecutor`; do not redeclare them in executor.go. `BackgroundExecutor.Spawn` / `ForegroundExecutor.Spawn` take `func(*scheduler.Scope) (R, error)`.
- M0-app-core / M0-app-effects / M0-app-contexts: AppContext primitives and free functions follow upstream's trait return types at this commit (plain values; only update_window / read_window return error, with_window `(R, bool)` and takes an `EntityID`), not DESIGN 6.2's all-error sketch. The extra primitive `newEntity` exists because `App::new` pushes `EntityCreated`. `App`'s primitive stubs and the delegate methods are in stubs.go; `*App` implements `borrowApp` in gpui.go (keep it there).
- M0-entities: `Entity[T]` embeds `AnyEntity` and `WeakEntity[T]` embeds `AnyWeakEntity` (upstream's `#[deref]`); gpui.go relies on `IntoAny`, `Downgrade`, `Clone`, `Read`, `EntityID` and the unexported `slot[T]` (embedding `Entity[T]`) and `entityFromAny[T]`.
- M0-element: gpui.go relies on `anyViewDowncast[V](AnyView) (Entity[V], bool)`, which must return an alias of the root (no new count: `AppContextReadWindow` passes it to `read` as a borrow and does not release it); `(Window).ReplaceRoot[V]` and `Focusable` / `(FocusHandle).Focus` / `Release` are used by the VisualContext free functions.
- M0-app-effects: `newGpuiBorrow(handle, app)` receives a borrowed handle (`AppContextAsMut` does not clone); start the update and take the lease from it without releasing it, which nets to upstream's clone-and-drop in `GpuiBorrow::new`.
- M0-exit: DESIGN 6.2's primitive and free-function sketch is superseded by docs/api-contracts.md section 2: `AppContextNew` / `ReserveEntity` / `InsertEntity` / `UpdateEntity` / `ReadEntity` / `ReadGlobal` / `AsMut` return plain values as upstream's trait does, `asMut` returns `*App`, `withWindow` takes an `EntityID` and returns `(R, bool)`, `AppContextUpdateWindow` exists, `newEntity` is an extra primitive, and background spawns take `func(*scheduler.Scope) (R, error)`. Reconcile DESIGN 6.2 with it.
