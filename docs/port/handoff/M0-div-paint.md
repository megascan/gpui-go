# M0-div-paint handoff

1. `Window.Spawn` (window_paint.go:594-600, also `SpawnWithPriority`) builds its AsyncWindowContext from `app.clone()`, which sets `Scope = nil`; any `Await(cx)` inside the closure panics with a nil dereference in scheduler/future.go:137 (`Scope.context`). Repro: in a `RunTest` window update, `window.Spawn(cx, func(cx *AsyncWindowContext) (struct{}, error) { _, _ = cx.BackgroundExecutor().Timer(time.Millisecond).Await(cx); return struct{}{}, nil })`, then `AdvanceClock` + `RunUntilParked`. Fix: keep the spawned task's scope (pass `app` itself, or copy `app.Scope` into the child). Then `windowSpawn` in elements_div_paint.go can call `window.Spawn` again (debt entry).
2. Test teardown (`TestAppContext.Close`, `TestRun.teardown` via `releaseAppWindows`, and `Window.RemoveWindow`) never releases the window's root view handle and never clears `renderedFrame` / `nextFrame` tab stops, so every window test reports "Handle for entity <root> was collected without Release" and, with focusable elements, "Focus handle ... was collected without Release". Repro: `RunTest` + `cx.AddWindow` of a view rendering `Empty{}` + one draw. window_smoke_test.go and elements_div_test.go (`divTestReleaseRoot`) work around it by clearing tab stops in one update and taking/releasing the root plus `RemoveWindow` in the next; drop the helpers once teardown does this (owner: M0-window-tests or M0-exit).
3. New stubs in stubs.go with final signatures: `(*windowA11y).setFocusable(a11y.NodeID, FocusID)`, `setFocus(a11y.NodeID)`, `noteFocusWithoutNode(FocusID, string)`, `setActiveDescendant(a11y.NodeID)` for M0-window-a11y (only reached while `isActive()`); `(*WrappedLine).Paint(origin Point[Pixels], lineHeight Pixels, align TextAlign, bounds Option[Bounds[Pixels]], window *Window, cx *App) error` and `(*WrappedLine).Size(lineHeight Pixels) Size[Pixels]` for M0-text-elements (used by the debug-assertions `paintDebugInfo`). docs/api-contracts.md section 1 should list them (not owned here).
4. Tooltip machinery for M0-text-elements (InteractiveText), all in elements_div_paint.go: `*activeTooltipCell` (upstream `Rc<RefCell<Option<ActiveTooltip>>>`; `set`, `replace`, `take` drop/cancel the old task), `clearActiveTooltip(cell, window)`, `clearActiveTooltipIfNotHoverable`, `setTooltipOnWindow(cell, window) Option[TooltipID]`, `registerTooltipMouseHandlers(cell, tooltipID Option[TooltipID], build tooltipBuildFunc, checkIsHovered, checkIsHoveredDuringPrepaint func(*Window) bool, longPressTooltipActive *bool, showDelay Option[time.Duration], window)`, `type tooltipBuildFunc func(window *Window, cx *App) (view AnyView, hoverable bool, ok bool)`.
5. Five div tests are written in full behind `t.Skip("blocked:M0-text-elements: ...")` because the tooltip view and the fallback prompt render text (`SharedString.IntoAnyElement` stub): LongPressShowsTooltipUntilTouchEnds, TooltipRespectsCustomShowDelay, TooltipIsReleasedWhenItsOwnerDisappears, TooltipHidesAfterMouseLeavesOrigin, MouseDownOutIsSuppressedWhileWindowPromptIsActive. M0-text-elements (or the next exit) removes the skips and flips the rows in core-elements.md to `done`.
6. `Interactivity.Prepaint` is a generic method `Prepaint[R any](..., f func(style *Style, scrollOffset Point[Pixels], hitbox Option[Hitbox], window *Window, cx *App) R) R`; `RequestLayout` / `Paint` / `ComputeStyle` keep upstream's shapes. `Div` implements `Element[DivFrameState, Option[Hitbox]]`, `ElementA11y` and `ElementA11ySyntheticChildren[Option[Hitbox]]`. `ScrollHandle` is a value aliasing shared state (create with `NewScrollHandle`; the zero value is unusable).

7. Tooltip view ownership: setTooltipOnWindow aliases the AnyView into frame.tooltipRequests (no Clone); activeTooltipState.drop releases it. Frame clear never releases tooltipRequests views. Probing the 4 skipped tooltip tests with a text-less view showed leaked-handle reports (both clone and alias variants). Whoever un-skips them must settle ownership: clone per request + release in frame.clear.
