# M0-elements-basic handoff

- M0-list: `ListSizingBehavior` and `ListHorizontalSizingBehavior` are stubs at the end of `stubs.go` with their final shape; move them into `elements_list.go`. The zero value of each is upstream's `#[default]` (`ListSizingBehaviorAuto = 0`, `ListSizingBehaviorInfer = 1`; `ListHorizontalSizingBehaviorFitList = 0`), following the Display convention. `NewUniformList` sets both explicitly.
- M4-ci-macos (macOS, fix authority) and M4-ios-app / M4-ios-window (iOS): `elements_surface.go` declares `RegisterSurfaceSourceSize(func(surface uintptr) Size[DevicePixels])`. Register a function returning `CVPixelBufferGetWidth` / `CVPixelBufferGetHeight` from `init`; `Surface.Paint` panics on darwin / ios when none is registered (D-SURFACE).
- Exit stage (window_paint.go owner): `Window.Spawn` builds its `AsyncWindowContext` from `app.clone()`, which sets `Scope = nil`, so any `Await` inside the spawned closure (e.g. `cx.BackgroundExecutor().Timer(d).Await(cx)`) panics with a nil dereference. Repro: in a `RunTest` window, `window.Spawn(cx, func(cx *AsyncWindowContext) (struct{}, error) { _, _ = cx.BackgroundExecutor().Timer(time.Millisecond).Await(cx); return struct{}{}, nil }).Detach()` then `cx.RunUntilParked()`. `elements_animation.go` uses the unexported `windowSpawn` helper (elements_div_paint.go), which passes the AsyncApp through, as the tooltip code does.
- Exit stage (app_context.go owner): `Context[T].Processor` captures a strong `cx.Entity()` that is never released, so strict leak detection reports "collected without Release" whenever the returned closure is dropped (upstream drops the clone with the closure). `elements_uniform_list_test.go` uses a local weak-entity processor (`uniformListTestProcessor`) instead; switch it back to `cx.Processor` once fixed.
- Exit stage: add stub-owner rows (owner M0-list) for `ListSizingBehavior` and `ListHorizontalSizingBehavior` to docs/api-contracts.md section 1.
