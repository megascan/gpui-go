## Threat model

gpui-go is a UI library. The attacker is whoever authors data the library parses or acts on for an app:
- remote servers behind image/SVG/font URIs (`img(uri)`, `ImageAssetLoader`, web `FetchHTTPClient`);
- other clients of the same session: clipboard/primary-selection owners, drag sources, any X11 client (ClientMessage, root properties, XIM server), Wayland compositor (semi-trusted), D-Bus session peers, AT-SPI bus clients, PipeWire;
- content an app commonly forwards to library APIs: link targets passed to `OpenURL`, dropped paths passed to `OpenWithSystem`/`RevealPath`, document images/SVGs, user-supplied fonts, user keymap/settings JSON.

Same-user peers that could already ptrace the app gain little (LOW at most) unless the vector also works from a sandboxed (flatpak/portal) peer or a remote source. The library opens no listeners (grep `net.Listen|ListenAndServe` outside tests: none) and writes no files outside generators (`internal/taffy/internal/mkfixtures`, `a11y/internal/gen`). Upstream parity matters: every finding records "also in upstream GPUI?" because fixes need a `dev:<id>` deviation (docs/port/PARITY.md §5).

Boundary: remote image server / document author / clipboard owner → decoder in app process.
